# 操作、驗證與部署

## 使用網站

1. `npm run dev`，開啟 http://localhost:3000 。
2. 預設可直接看三場已驗證快照；日期欄查詢當日官方賽程。
3. 點場次後取得資料並顯示分析。賽事類別只篩選場次；局數／投手／投球結果只篩選球點、球種與逐球表。
4. 球員表現與比分始終為全場；得分事件也顯示全場。
5. 原始 JSON 保留官方內容；分析 JSON 含資料來源、時間、分析版本及計算結果；CSV 匯出當前投球與搜尋篩選。
6. 官方暫時無法連線時嘗試收錄的靜態資料，並清楚標示快照／批次來源。未收錄場次會提示錯誤，不替換成別場比賽。

## 已完成驗證

- 三場原始樣本及額外兩場無 Trackman 資料的比賽，重建投球數與官方用球一致，逐局比分加總與結果一致。
- 瀏覽器實測賽程查詢、局數篩選、打者頁籤、得分事件、原始 JSON 下載；下載 JSON 與保存的原始樣本內容相等。
- 手機 390px 視窗檢查無頁面橫向溢出；寬表格在個別容器橫向捲動。
- 自動測試包含真實樣本核對、特殊事件與無投球裁定、缺漏、CSV 公式與換行處理、API 日期及 ID 驗證、GET 限制、快取與重複請求合併。

逐球辨識包含有實際投球的盜壘／牽制附帶事件，排除換人與未投球裁定。無追蹤判決時，明確文字可補入投球分類並標示來源。跨球季或不同官方格式仍可能有未支援事件；差異不會被默默修正。

## Vercel 部署

1. 在 Vercel 登入自己的帳號並連結 GitHub，匯入 https://github.com/lokcyi/cpbl 。
2. 個人非商業用途可選 Hobby。維持 repository root 為根目錄、Framework Preset 為 Other。
3. 使用已提交的 `vercel.json`：建置 `npm run build`、輸出 `dist`、API 最長執行 30 秒（上游逾時 20 秒）。
4. 部署後確認 `/`、`/api/schedule?date=2026-07-21`、`/api/game?id=2026-A-211` 正常。
5. 選一場官方資料完整的場次，確認來源標示官方連線，下載並核對。

若使用 CLI，先在自己的終端完成 `vercel login`，再以 `vercel` 建立預覽、確認後 `vercel --prod`。本次環境的 Vercel 登入憑證無效，因此未宣稱已正式上線。GitHub repo push 與 Vercel 帳號登入是不同權限。

## 批次收錄

```sh
npm run refresh -- 2026-07-21
```

輸出 `data/schedule/`、`data/games/`、`data/analysis/`、`data/manifest.json`，保留原始回應、分析與取得時間。只收錄已完賽場次。分析在頁面也會由當前版本重新計算，避免舊分析直接誤用。

GitHub Actions 的 `Collect finished games` 工作可手動指定日期，抓取後提交到 main。未啟用定時排程。Workflow 寫入 GitHub 的權限僅存在 Actions，不放在公開網頁。

少量批次資料隨部署發布；長期整季歷史版本應改用物件儲存，以免 Git 歷史持續膨脹。由 Actions bot 產生的資料更新，仍需確認 Vercel 專案的 Git 整合是否觸發部署；必要時手動 Redeploy。

## 資料限制

- 主審頁提供身高比例框的模型相符率、各打者球點與判決明細；不等同正式 ABS 準確率。詳見 [主審分析方法](umpire-analysis.md)。不計算 ABS 挑戰率。
- 球點保留原始軸值，不假設捕手或投手視角。
- 球種使用自動標籤，原始人工標籤保留 CSV；不將單一球種分類當成已驗證事實。
- 球數為事件後狀態；不同資料欄位的前後狀態不可混用。
- 不提供勝率模型、球員綜合百分制、登入、永久資料庫或即時轉播。
- API 只允許固定官方路徑，內含短期記憶體快取與 CDN 快取；不是跨執行環境的永久儲存或完整限流服務。
- 靜態資料備援主要支援 Vercel；本版使用根路徑，不適合直接放在 GitHub Pages 的 `/cpbl/` 子路徑而不調整網址。

## 維護

`npm test` → `npm run build` → GitHub CI 驗證通過 → Vercel 部署。無需 npm install。若擴充資料欄位，先使用官方樣本核對分母與事件分類。
